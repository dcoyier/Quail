Moving beyond retrieval

Quail lets an AI agent make sense of a large text dataset the way an analyst would in a notebook, one cell at a time, with every step saved.

Researchers often have more text than anyone can read closely. Campus offices, for example, collect open-ended survey answers that nobody has time to read in full.1 Retrieval-augmented generation (RAG)2 helps a language model with a dataset like that by handing it the few passages that best match a question. That can answer “what did the news say about lines at the polls?” but not “how often did it come up, and on which networks?”

Quail builds on RAG by letting the agent count as well as retrieve. A count covers every match in the dataset and can be split by any field, so the agent can check how common something is instead of guessing from a few examples. Labels, which Quail calls tags, record what it decides as it reads.

A notebook for an agent

A Jupyter notebook lets an analyst try something, read the result and decide what to try next, and Quail gives an agent the same loop. Each quail exec sends one cell of Python to a kernel that stays alive between calls, and the agent reads back what a notebook would show: printed output, the last line’s value, or a traceback.

Searching, counting and tagging could have been separate tool calls. Instead they form a small Python library, so one cell can combine them and return only what matters. Cloudflare’s Code Mode makes the same choice for MCP tools but starts a fresh sandbox for each snippet;3 Quail keeps its kernel from one cell to the next.

The host saves each cell to the session log before replying, so any reply means the work is on disk. The index can be rebuilt from the study’s files.

This session comes from a study of 3.3 million segments of TV news from six elections, 2004 to 2024. The agent searches the 323,464 segments from 2012 for voters waiting in line at the polls. Five cells follow, verbatim; gaps in numbering are cells left out.

Studies live in git

A study is an ordinary folder of text files, so git can share it the way it shares code. Each kernel run writes its own log file, which means agents working in parallel never edit the same file. To try another approach without disturbing the first, quail fork copies a closed session’s tags and history into a new session.

Semantic search needs an embedding for every distinct text, and computing them the first time can take hours. quail warm can do that work in advance, split across several machines, and save it in warm/, so every clone of the study starts with it.

Where Quail can run

Quail needs only a shell, so it can run wherever an agent does, on a laptop or a cloud VM. In one tested setup, the TV news study from the example was available in Slack. Mentioning @Cursor in a thread started a Cursor cloud agent on its own VM, booted from a snapshot that already held Quail, an embedding model and the fully processed dataset, so the agent could search all six years without any setup.

Status and next steps

Quail 0.94 is an alpha release for Linux and macOS, open source under the Apache 2.0 license, and it works with any agent that can run shell commands. Nothing it has produced has been formally evaluated yet, and working out how to do that well is our next step. If you have a text dataset you would like to understand, we would love to hear about it.

To try it, with Python 3.12+ and uv: $ git clone --depth 1 https://github.com/dcoyier/Quail.git $ cd Quail && uv sync --locked --no-dev --python 3.12 $ . .venv/bin/activate && quail init ../my-study
