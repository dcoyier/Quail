Beyond retrieval

Quail lets an AI agent make sense of a large text dataset in a notebook, with tools it can combine in code.

Researchers often have more text than anyone can read closely.1 Retrieval-augmented generation (RAG)2 helps an agent with a large dataset by handing it the few entries that best match a question. This can answer “what did the news say about lines at the polls?” but not “how often, and on which networks?”

Quail builds on RAG. It keeps retrieval and adds three more functions: count and values work over every matching entry, not just the closest few, so the agent can check how common something is instead of guessing from examples, and tag saves its analysis on the entries themselves.

A notebook for an agent

A Jupyter notebook lets a researcher try something, read the result and decide what to try next. Quail gives an agent the same loop. Each cell the agent sends runs in a kernel that stays alive between cells, and the agent gets back what a notebook would show: printed output, then the last line’s value or a traceback.

Many systems give an agent a separate tool for each operation, such as search or count. Quail gives it a Python kernel instead, where searching, counting and tagging are functions in Quail’s analysis language, so one cell can combine them and return only what matters. Cloudflare’s Code Mode makes the same choice for MCP tools but starts a fresh sandbox for each snippet;3 Quail keeps its kernel from one cell to the next.

The session host saves each cell to the session log (5) before replying (7), so every result is already on disk. The index is only a cache of the study’s files.

The analysis language

Cells combine ordinary Python with Quail’s analysis language. Its pieces build on one another, from the columns of a dataset to four core functions.

Studies live in git

A study is an ordinary folder of text files, so git can share it the way it shares code. Each kernel run writes its own log file, so agents working in parallel push separate files that merge without conflicts. To branch an analysis without disturbing the original, an agent can copy a closed session’s tags and history into a new session.

Semantic search needs embeddings of every distinct value in a field, which can take hours to compute. quail warm can compute them ahead of time, in shards on several machines, and save them in warm/, so every clone starts with them.

Where Quail can run

Quail needs only a shell, so it runs wherever an agent does, on a laptop or a cloud VM. For example, in one tested setup, mentioning @Cursor in a Slack thread started a Cursor cloud agent on its own VM. The VM booted from a snapshot that already held Quail, an embedding model and the dataset, indexed and embedded, so the agent could start without any setup.

Status and next steps

Quail 0.94 is an alpha release for Linux and macOS, open source under the Apache-2.0 license. It works with any agent that can run shell commands.

Open questions

  1. How does Quail add value to coding agents such as Codex or Claude Code?
  2. Is semantic search really helpful?
  3. Could Quail search and tag passages within a text without chunking it first?
  4. How could “System 1” decision models such as Jev be integrated into Quail?
  5. How can an agent communicate its method efficiently, so that researchers can trust its analysis?
To try it, with git and uv installed: $ git clone --depth 1 https://github.com/dcoyier/Quail.git $ cd Quail && uv sync --locked --no-dev --python 3.12 $ . .venv/bin/activate && quail init ../my-study
