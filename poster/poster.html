Beyond retrieval

Quail lets an AI agent make sense of a large text dataset the way an analyst would in a notebook, one cell at a time, with every step saved.

Researchers often have more text than anyone can read closely, from the open‑ended survey answers that campus offices collect1 to TV news coverage of six elections. Retrieval-augmented generation (RAG)2 helps a language model with a dataset like that by handing it the few entries that best match a question. That can answer “what did the news say about lines at the polls?” but not “how often did it come up, and on which networks?”

Quail builds on RAG: the agent can count and tag as well as retrieve. A count covers every match in the dataset and can be split by any field, so the agent can check how common something is instead of guessing from a few examples. Tags record what the agent decides, such as which matches fit.

A notebook for an agent

A Jupyter notebook lets an analyst try something, read the result and decide what to try next. Quail gives an agent the same loop. Each quail exec sends one cell of Python to a kernel that stays alive between calls, and the agent reads back what a notebook would show: printed output, then the last line’s value or a traceback.

Searching, counting and tagging could have been separate tool calls. Instead they are part of Quail’s analysis language, a small Python library, so one cell can combine them and return only what matters. Cloudflare’s Code Mode makes the same choice for MCP tools but starts a fresh sandbox for each snippet;3 Quail keeps its kernel from one cell to the next.

The session host saves each cell to the session log (5) before replying (7), so every result is already on disk. The index is only a cache of the study’s files.

An example session

This session comes from a study of 3.3 million segments of TV news from six elections, 2004 to 2024. The agent searches the 323,464 segments from 2012 for voters waiting in line at the polls. Five cells follow, verbatim apart from one renamed tag; gaps in numbering are cells left out.

Studies live in git

A study is an ordinary folder of text files, so git can share it the way it shares code. Each kernel run writes its own log file, so agents working in parallel push separate files that merge without conflicts. To try another approach without disturbing the first, quail fork copies a closed session’s tags and history into a new session.

Semantic search needs embeddings of every distinct value in a field, which can take hours to compute. quail warm can compute them ahead of time, in shards on several machines, and save them in warm/, so every clone starts with them.

Where Quail can run

Quail needs only a shell, so it runs wherever an agent does: on a laptop or a cloud VM. In one tested setup, mentioning @Cursor in a Slack thread started a Cursor cloud agent on its own VM. The VM booted from a snapshot that already held Quail, an embedding model and the example’s TV news study, indexed and embedded, so the agent could search all six elections without any setup.

Status and next steps

Quail 0.94 is an alpha release for Linux and macOS, open source under the Apache-2.0 license. It works with any agent that can run shell commands. Its results have not yet been formally evaluated, and working out how to do that well is our next step. If you have a text dataset you would like to understand, we would love to hear about it.

To try it, with git and uv installed: $ git clone --depth 1 https://github.com/dcoyier/Quail.git $ cd Quail && uv sync --locked --no-dev --python 3.12 && . .venv/bin/activate $ quail init ../my-study
