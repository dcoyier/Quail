ClerkMcpRuntime remembers clerk-mode MCP dependencies (db path, feedback, users,
verifier, sticky store, host, port, optional SearchRuntime,
include_dataset_docs_in_setup).

create_mcp_server(db_path, feedback_path, workspace_id default local, api_docs_path default None,
                  host default 127.0.0.1, port default 8000,
                  search_runtime default None, connector_catalog default None,
                  include_dataset_docs_in_setup default false):
  Remember unrestricted McpContext with db_path (not a live CoreDb), optional
  api_docs_path override (None uses packaged docs via load_api_docs), and optional
  SearchRuntime.
  Build FastMCP with unrestricted instructions.
  Register the core unrestricted async tools (including quail_setup;
  bodies via run_blocking) and give back the server.

create_mcp_server_from_config(config, api_docs_path default None, verifier default None):
  Configure process-wide exec slots from config.max_concurrent_executions.
  Build SearchRuntime from config when search_database is set.
  Load the connector catalog.
  If unrestricted, build create_mcp_server from config paths (pass
  include_dataset_docs_in_setup).
  If clerk, build create_clerk_mcp_server with ClerkJwtVerifier or the given verifier.
  Give back PreparedMcp (server, search_runtime, connector_catalog).

PreparedMcp remembers server, optional search_runtime, optional connector_catalog.
close(): close the search pool and call ConnectorCatalog.close when present.

create_clerk_mcp_server(config, verifier, api_docs_path default None,
                        search_runtime default None, connector_catalog default None):
  Remember ClerkMcpRuntime (build search runtime from config when omitted;
  include_dataset_docs_in_setup from config). Build ClerkJwtVerifier with
  config.clerk_authorized_parties when verifier is omitted.
  Build FastMCP with locking-agnostic clerk instructions, MCP AuthSettings
  (Clerk issuer + public /mcp resource), and ClerkAccessTokenVerifier
  (token verify plus TOML [[users]] allowlist).
  Register /.well-known/oauth-authorization-server proxy for older clients.
  Register list/switch plus gated analysis tools (including quail_setup) and give
  back the server.
  Connector HTTP file routes authenticate Bearer and require workspace membership.
  Clerk session create stamps owner_user_id; exec, export, and feedback-with-session
  require that owner.

All tools are async and offload blocking work with run_blocking.
Unrestricted tools open CoreDb per call from context.db_path.
_export_csv_payload(db, session_id, dataset_id, db_path):
  Lock the session, write the CSV under <db-parent>/exports, and give back
  path, session_id, dataset_id, dataset_version_id, columns, and row_count.
quail_export_csv: session lock, write source plus this session's analysis
  fields to <core-db-parent>/exports/<dataset_id>.<session_id>.csv, and give
  back path, columns, and row_count. It does not process or write TOML. The
  path is on the serve host.
quail_setup returns documentation, datasets, session_id, workspace_id, and
state_revision (optionally per-dataset documentation when configured).
quail_exec passes context.search_runtime into exec_script (pool checkout per exec).

Clerk tools:
  Authenticate Bearer via override or request headers.
  Sticky-bind default_workspace once per Streamable HTTP connection
  (mcp-session-id header), falling back to the Clerk user id when no
  connection id is present (in-process tests).
  Core tools re-check that the sticky workspace is still a membership.
  quail_list_workspaces returns memberships (or only default when locked) and active_workspace_id.
  quail_switch_workspace binds an allowlisted workspace or errors when locked.
  Dataset/session/setup/exec/export/feedback require an active workspace; unbound gets UNBOUND_REPAIR_HINT.
  quail_export_csv uses require_owned_active_session then _export_csv_payload.
  quail_exec passes runtime.search_runtime into exec_script.
