There is a default workspace id called local.

Resolvers are the only seam between the two auth modes. A workspace resolver
gives back (workspace_id, user_id) or an error CallToolResult to return as-is;
a user resolver gives back user_id (or None) the same way. user_id is None in
unrestricted mode and the TOML [[users]].id in Clerk mode; every ownership
difference between the modes hangs off that.

_ToolHost remembers everything the core tools need, however the server was built:
  db_path (not a live CoreDb)
  feedback_path
  api_docs_path (optional override; default uses packaged docs/api.md)
  search_runtime (optional SearchRuntime with pooled SearchDb)
  include_dataset_docs_in_setup
  connector_catalog
  resolve (workspace resolver)
  resolve_user (user resolver)

ClerkMcpRuntime remembers clerk-mode MCP dependencies (db path, feedback, users,
verifier, sticky store, optional SearchRuntime,
include_dataset_docs_in_setup).

PreparedMcp remembers server, optional search_runtime, optional connector_catalog.
close(): close the search pool and call ConnectorCatalog.close when present.

create_mcp_server(db_path, feedback_path, workspace_id default local, api_docs_path default None,
                  search_runtime default None, connector_catalog default None,
                  include_dataset_docs_in_setup default false):
  Build a _ToolHost whose resolvers always give back the fixed workspace_id
  with user_id None.
  Build MCPServer with unrestricted instructions, register the core tools, and
  give back the server. Bind address is chosen later at serve run.

create_mcp_server_from_config(config, api_docs_path default None, verifier default None):
  Configure process-wide exec slots from config.max_concurrent_executions.
  Build SearchRuntime from config when search_database is set.
  Load the connector catalog.
  If unrestricted, build create_mcp_server from config paths (pass
  include_dataset_docs_in_setup).
  If clerk, build create_clerk_mcp_server with ClerkJwtVerifier or the given verifier.
  Give back PreparedMcp (server, search_runtime, connector_catalog).

create_clerk_mcp_server(config, verifier, api_docs_path default None,
                        search_runtime default None, connector_catalog default None):
  Remember ClerkMcpRuntime (build search runtime from config when omitted;
  include_dataset_docs_in_setup from config). Build ClerkJwtVerifier with
  config.clerk_authorized_parties when verifier is omitted.
  Build MCPServer with locking-agnostic clerk instructions, MCP AuthSettings
  (Clerk issuer + public /mcp resource), and ClerkAccessTokenVerifier
  (token verify plus TOML [[users]] allowlist).
  Register /.well-known/oauth-authorization-server proxy for OAuth clients
  that look up AS metadata on the resource origin.
  Register the clerk list/switch workspace tools, then the same core tools with
  clerk resolvers, and give back the server.
  Connector HTTP file routes authenticate Bearer and require workspace membership.

_run_tool(work, on_error default None):
  Run the tool body off-loop with run_blocking. If it raises, give back
  on_error(error) when provided, else error_result(error). Every tool funnels
  through this; no tool carries its own try/except.

_session_gate(db, session_id, user_id):
  Give back the active session. When user_id is set (Clerk), also require that
  the session is owned by that user. The caller checks the workspace.

_export_csv_payload(db, session_id, dataset_id, db_path):
  Lock the session, write the CSV under <db-parent>/exports, and give back
  path, session_id, dataset_id, dataset_version_id, columns, and row_count.

_register_core_tools(server, host):
  Register the frozen core tool surface once; modes differ only in resolvers.
  Every tool resolves its scope first (returning the resolver's error result
  when auth or bind fails), then does its work.
  quail_setup: build the setup payload (documentation, datasets, a fresh
    session stamped with user_id, workspace_id, state_revision; optionally
    per-dataset documentation when configured). Errors add the api-docs +
    core-DB repair hint.
  quail_get_api_docs: user resolver only (no workspace bind); give back the
    packaged or overridden analysis docs. Errors add the api-docs repair hint.
  quail_list_datasets: list dataset_id, name, active_version_id for the
    bound workspace.
  quail_start_session: create_session in the bound workspace with user_id as
    owner; give back session_id, workspace_id, state_revision.
  quail_get_dataset_info: require the dataset in the bound workspace; give
    back identity plus connector documentation (or the short fallback).
  quail_exec: validate time_window, gate the session (_session_gate plus
    workspace check), run exec_script with host.search_runtime (pool checkout
    per exec), and give back printed_output. Errors carry execution_id null
    and _exec_repair_hint.
  quail_export_csv: gate the session the same way, then _export_csv_payload.
    It does not process or write TOML. The path is on the serve host.
  provide_feedback: when session_id is given, require it to exist (and, in
    Clerk mode, be owned by user_id); when dataset_id is given, require it in
    the bound workspace; then append to the feedback file.

Clerk resolvers:
  _clerk_auth: authenticate Bearer via override or request headers; on auth
    failure give back an error result with a mode-appropriate repair hint.
  _clerk_workspace: sticky-bind default_workspace once per Clerk user
    (user:{clerk_user_id}). Unbound gets UNBOUND_REPAIR_HINT; a stale bind
    must still be a membership.
  _clerk_resolve: auth then workspace; give back (workspace_id, user_id).
  _clerk_resolve_user: auth only; give back user_id.

_register_clerk_workspace_tools(server, runtime):
  quail_list_workspaces returns memberships (or only default when locked) and
    active_workspace_id.
  quail_switch_workspace binds an allowlisted workspace for this Clerk user
    on this process (every MCP connection as that user shares the bind), or
    errors when locked.

_authorization_header: read Bearer from override or request headers.
_clerk_connection_key: user:{clerk_user_id}. Sticky is per Clerk user for
  this process, not per transport session.
_exec_repair_hint: prefer QuailRuntimeError.repair_hint over the generic exec
failure hint.
_build_setup_payload / _dataset_documentation: assemble the quail_setup payload
and resolve connector docs (else the short fallback string).
