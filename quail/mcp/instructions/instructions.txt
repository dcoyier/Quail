There are repair hint strings for unbound and locked workspace cases.
There is a private locked-user instructions addendum.
There is a private session-rules string (workspace-scoped sessions; after switch
call quail_setup or quail_start_session again; one quail_exec in flight per
session_id; overlap fails with session_busy).
There is a private Clerk session-rules string (same, plus sessions are owned by
the creating user; do not use another user's session_id).

There is a private export-rules string (quail_export_csv writes a serve-host
CSV of source plus this session's tags; path is not a download; that is the
route to warm-path speed after process makes those columns source; export
does not reprocess; do not overlap with quail_exec).

unrestricted_instructions(workspace_id):
  Give back fixed-workspace connect-time instructions (unrestricted; no sign-in)
  preferring quail_setup → dataset info → exec, including session rules, the
  skip-get_dataset_info-when-docs-already-in-setup note, and the export rules.

clerk_instructions(locked default false):
  Give back Clerk identity-mode bind-then-quail_setup instructions: token proves
  identity, TOML allowlist gates access, authorized parties bind the app; scopes
  are advertised for clients but not enforced from the token. Include Clerk
  session ownership rules, the dataset-docs note, and the export rules.
  When locked is true, append the locked-user addendum.
