Register connected connector tools, resources, widgets, and HTTP routes on FastMCP.

There is a frozen set CORE_MCP_TOOL_NAMES of core Quail MCP tool names
(unrestricted plus Clerk workspace tools).

register_connectors(server, catalog, resolve_workspace, authenticate_route default None):
  Attach tools/resources/widgets/routes. resolve_workspace receives FastMCP
  Context (or None) and returns workspace_id and optional user_id.
  authenticate_route, when set, authenticates connector file GETs.
  Reject when two different connectors claim the same tool name or resource URI.
  Reject when a connector tool name matches a core Quail MCP tool (quail_exec,
  quail_export_csv, and the rest of the frozen host surface) or is already
  registered on the server.
  FastMCP overwrites duplicate add_tool names with a warning, so this fails closed.
  The same connector may expose the same tool/URI across workspaces.
  Tool handlers fail when the tool is not active in that workspace. Required tool
  parameters are bound before optional ones and Context (annotated so FastMCP
  injects it and does not advertise ctx on tools/list).
  Omit optional arguments whose bound value is None so connectors that use
  dict.get(name, default) still see the default. Required arguments that are
  None still fail as missing.
  After add_tool, publish ToolSpec.input_schema onto the FastMCP tool parameters
  so tools/list shows the real JSON Schema (not the Any signature).
  Wrap Tool.run so live calls validate raw arguments against that schema before
  FastMCP strips extras: extra keys, missing required (including null), and
  wrong types become ConnectorError INVALID_ARGUMENTS (no Pydantic leak).
  Omit-None for optional keys still happens inside the handler after validation.
  When any connector tools were registered, wrap FastMCP list_tools (and the
  low-level MCP handler) so tools/list uses the same resolve_workspace as calls.
  Core tools stay listed. A connector tool is listed only when
  _provider_for_workspace finds an owner for the active workspace.
  When resolve_workspace raises (unbound Clerk, missing auth), omit connector
  tools rather than listing the union.
  ToolResult structured_content becomes structuredContent; optional text becomes
  the MCP text content block (not merged into structured content). When text is
  omitted and images are present, content is image-only. Optional images become
  MCP ImageContent blocks after any text block.

Routes mount at /extensions/{extension_id}/{workspace_id}/{path_suffix} for each
RouteSpec. GET only. Optional authenticate_route(request, workspace_id) runs
first: give back user_id, or raise UnauthorizedError (401) / ForbiddenError (403).
Unrestricted omits it and passes user_id None. The handler then resolves the
workspace-bound provider, calls handle_route, and streams FileResponse bytes
(404 when None). If FileResponse.expires_at is in the past, give back 404
instead of the file. Remaining lifetime becomes Cache-Control max-age.

_install_workspace_scoped_list_tools(server, providers_by_tool, resolve_workspace):
  Remember the current FastMCP list_tools.
  Replace it and the low-level MCP list_tools handler with a wrapper.
  The wrapper lists tools, then resolve_workspace from server.get_context().
  Give back _tools_visible_in_workspace. If resolve_workspace raises, treat
  workspace_id as missing.

_tools_visible_in_workspace(tools, providers_by_tool, workspace_id):
  Give back core tools (names not in providers_by_tool) always.
  Give back a connector tool only when workspace_id is set and
  _provider_for_workspace finds an owner.
