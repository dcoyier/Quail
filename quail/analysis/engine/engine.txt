QueryEngine evaluates plans for one Scope against catalog data and an in-memory overlay.

It remembers db, scope, optional SimilarityService, optional LexicalService, staged
mutations, created fields, value overlay, and a per-exec Lexical/Semantic score cache.

mutations:
  Give back the staged FieldCreate, ValueWrite, and ValueDelete tuple.

resolve_field(field):
  Resolve a Field or name against the catalog.
  When kind is set and does not match the catalog, raise QuailFieldError.
  Unknown names raise QuailFieldError.

check_bound_field_kind(field):
  When field.kind is set and the name exists in the catalog with a different
  kind, raise QuailFieldError.
  kind=None and unknown names do nothing (forward refs stay allowed on bind).

retrieve(plan):
  For fields units, evaluate the field group and apply limit/order.
  Otherwise evaluate entry ids.
  For Unit("entries", field), keep only entries where the field is present.
  Then apply ranking and limit/order.
  Materialize Expression values, Entry handles, present field values, or distinct values.

count(plan):
  Same candidate sets as retrieve, but give back the length.

create_field(plan):
  Reject source-name collision.
  Stage FieldCreate when new and remember the analysis Field.

tag(plan):
  Require an analysis field (via resolve_field).
  For each selected entry, stage ValueWrite and update the overlay.

untag(plan):
  Clear matching overlay cells and stage ValueDelete.

entry_value / entry_fields:
  Read through overlay then durable source or analysis values (kind-checked).

Helpers evaluate groups and predicates, run expression pipelines (Value, AsText,
AsNumber, regex, Slice, Length, Lexical via LexicalService, Semantic via
SimilarityService). Before Lexical/Semantic scoring, resolve query targets from
LiteralText, LiteralTextList, EntryGroup, or EntryList using the expression root
field; Lexical Entry* targets are term-quoted. Predicates and rankings that end in
Lexical/Semantic share one per-exec score cache keyed by Expression.to_record():
each distinct search-terminal Expression is batch-scored once over needed entry
ids (gap-fill missing ids), then predicate filters and ranking reuse those scores.
