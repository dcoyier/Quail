QueryEngine evaluates plans for one Scope against catalog data and an in-memory overlay.

There is a repair hint _LEXICAL_NOT_CONFIGURED_HINT to pin core.search_database,
re-run quail process, restart quail run, then retry the whole exec.
There is a repair hint _SEMANTIC_NOT_CONFIGURED_HINT that also names
[providers.*] and [datasets.embedding].

It remembers db, scope, optional SimilarityService, optional LexicalService, staged
mutations, created fields, value overlay, a per-exec Lexical/Semantic score cache,
and an execution snapshot (ordered entry ids, positions, lazy per-field value maps,
catalog cache).

mutations:
  Give back the staged FieldCreate, ValueWrite, and ValueDelete tuple.

resolve_field(field):
  Resolve a Field or name against the catalog.
  When kind is set and does not match the catalog, raise QuailFieldError
  and mention del name then assign again if the Field is a stale binding.
  Unknown names raise QuailFieldError. If the name is id, say CSV id is
  entry.id. Otherwise say inspect retrieve(unit=fields, group=G1) or use
  entry.id. If that name is an analysis field on another version of this
  dataset in this session, append that tags are per dataset version and to
  retag on the active version.

_unknown_field_error(name, requested_kind):
  Build Unknown field / Unknown <kind> field.
  If the name is id, say CSV id is entry.id.
  Otherwise say inspect retrieve(unit=fields, group=G1) or use entry.id.
  If that name is an analysis field on another version of this dataset in this
  session, append that tags are per dataset version and to retag on the active
  version.

_analysis_name_on_other_version(name):
  Give back true when this session has that analysis field name on another
  version of this dataset.

check_bound_field_kind(field):
  When field.kind is set and the name exists in the catalog with a different
  kind, raise QuailFieldError.
  kind=None and unknown names do nothing (forward refs stay allowed on bind).

retrieve(plan):
  For fields units, evaluate the field group and apply limit/order.
  Otherwise evaluate entry ids.
  For Unit("values", field), collect distinct present values over the full
  entry group via _distinct_present_values, then apply limit/order to that
  distinct sequence (ranking is rejected at plan time).
  For Unit("entries", field), keep only entries where the field is present.
  Then apply ranking and limit/order.
  Materialize Expression values, Entry handles, or present field values.

count(plan):
  Same candidate sets as retrieve, but give back the length.
  Values-unit counts use len(_distinct_present_values(...)).

create_field(plan):
  Reject source-name collision.
  Stage FieldCreate when new and remember the analysis Field.
  Clear catalog and field-snapshot caches for that name.

tag(plan):
  Require an analysis field (via resolve_field).
  Require each Entry handle in a tuple group to belong to this scope.
  For each selected entry, stage ValueWrite and update the overlay.
  If any ValueWrite was staged, clear the per-exec Lexical/Semantic score cache.

untag(plan):
  Same scope checks as tag.
  Clear matching overlay cells and stage ValueDelete.
  If any ValueDelete was staged, clear the per-exec Lexical/Semantic score cache.

entry_value / entry_fields:
  Require the Entry handle to belong to this scope.
  Read through overlay then the field snapshot (bulk-loaded once per field).

_require_entry_in_scope(entry):
  When dataset_id or dataset_version_id is stamped and differs from scope,
  raise QuailScopeError.

Helpers evaluate groups and predicates, run expression pipelines (Value, AsText,
AsNumber, regex, Slice, Length, Lexical via LexicalService, Semantic via
SimilarityService). When LexicalService is missing, raise QuailRuntimeError with
repair_hint to set core.search_database, re-run quail process, then retry.
When SimilarityService is missing, the hint also names [providers.*] and
[datasets.embedding]. Member entry groups validate each member's scope.

_apply_regex(operation, value):
  Compile the pattern with flags.
  RegexSearch: None stays None; non-text raises to use AsText first; otherwise
    the first match or None.
  RegexFindAll: None stays []; non-text raises to use AsText first; otherwise
    the list of matches.
  RegexSub: None stays None; non-text raises to use AsText first; otherwise
    require text or list[text] and replace matches with the literal replacement.
Field-scoped member groups resolve each member through resolve_field against the
catalog (kind stamped; unknown or kind-mismatched names raise).
Field reads bulk-load each referenced field once into an entry_id map; overlay
wins. Ranking tie-breaks with a precomputed position map.

_apply_limit(items, limit, order):
  Give back top, bottom, or middle slice of items by order.
  Empty items give back [].

_distinct_present_values(field, entry_ids):
  Walk entry_ids in order.
  Skip None.
  Keep first-seen values by _distinct_value_key.
  Give back that distinct list.

_distinct_value_key(value):
  Give back json.dumps(value, sort_keys=True) when the value is JSON-serializable.
  Otherwise give back repr(value).

Before Lexical/Semantic scoring, resolve query targets from
LiteralText, LiteralTextList, EntryGroup, or EntryList using the expression root
field; Lexical Entry* targets are term-quoted. Predicates and rankings that end in
Lexical/Semantic share one per-exec score cache keyed by Expression.to_record():
each distinct search-terminal Expression is batch-scored once over needed entry
ids (gap-fill missing ids), then predicate filters and ranking reuse those scores.
For Lexical and Semantic, when there are no transforming prefix operations and
the root resolves to a source field, _bare_source_search_field gives that name.
Lexical first asks lexical_scores_for_source_entries to score those entry ids
directly without loading source values, and tells that path when the candidate
ids are the complete dataset. Semantic does the same via
semantic_scores_for_source_entries when the field was registered at embedding
warm. If the source field is not warmed (or not registered for Semantic),
materialize corpus values with _corpus_by_entry and use dynamic scoring (still
pass source_field so Lexical can reuse a warmed corpus when possible).
_warmed_lexical_source_field encodes the bare-source rule for scalar eval.

_corpus_by_entry:
  Materialize requested corpus values only for dynamic or unwarmed search.
  Apply transforming prefix operations when present.
