There is a set _ALLOWED_SCOPES of "entries", "fields", and "values".

Unit is an immutable description of what retrieve or count should return.
It is not which population to use — that is the group argument.

A Unit remembers:
  scope
  field (default None)

After creating a Unit:
  Require that scope is allowed.
  Require that field is a Field or None.
  Require that scope and field are a valid combination.

to_record:
  Give back a plain dictionary of scope and field.
  If field is present, store field.to_record(); otherwise store None.
  Used for debugging or later serialization.

entries:
  The builtin Unit with scope "entries".
  Means return Entry handles.

fields:
  The builtin Unit with scope "fields".
  Means return Field definitions.

_require_allowed_scope(scope):
  If scope is not in _ALLOWED_SCOPES, raise a syntax error that Unit scope must be "entries", "fields", or "values".

_require_field_type(field):
  If field is not None and not a Field, raise a syntax error that Unit field must be a Field or None.

_require_scope_field_combo(scope, field):
  If scope is "fields" and field is not None, raise a syntax error that Unit("fields", field) is invalid.
  If scope is "values" and field is None, raise a syntax error that Unit("values", field) requires a Field.
  If scope is "entries" and field is None, that means return Entry handles.
  If scope is "entries" and field is set, that means return present values of that field aligned to entries.
